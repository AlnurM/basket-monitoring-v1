**Handlers to implement (in this registration order -- FSM handlers before generic callbacks per Pitfall 5):**

1. **`cmd_baskets`** -- `@router.message(Command("baskets"))`
   - Guard: if user is None, show language selection (same pattern as cmd_help in start.py)
   - Create `BasketRepository(session)`
   - Call `repo.get_user_baskets_with_item_counts(user.id)`
   - If empty, send `get_text("baskets_empty", lang)` with `basket_list_keyboard([], lang)` (shows only New Basket button)
   - If baskets exist, send `get_text("baskets_title", lang)` with `basket_list_keyboard(baskets_with_counts, lang)`

2. **`cmd_new_basket`** -- `@router.message(Command("new_basket"))`
   - Guard: if user is None, show language selection
   - Check limit: `BasketRepository(session).count_by_user(user.id) >= settings.max_baskets_per_user`
   - If limit reached, send `get_text("basket_limit_reached", lang, max=settings.max_baskets_per_user)`
   - Otherwise, set FSM state `CreateBasket.waiting_for_name` and send `get_text("enter_basket_name", lang)`

3. **`receive_basket_name`** -- `@router.message(CreateBasket.waiting_for_name)`
   - Get name from `message.text.strip()`
   - Validate name is not empty, not too long (max 50 chars). If invalid, ask again.
   - Store name in FSM data: `await state.update_data(name=name)`
   - Do NOT clear FSM state here -- the name is stored in state data and will be read in the next handler (callback_set_source). State is cleared there after reading the name.
   - Send source selection keyboard: `get_text("choose_source", lang)` with `source_selection_keyboard(lang)`

4. **`callback_set_source`** -- `@router.callback_query(BasketCB.filter(F.action == "set_source"))`
   - Get source from `callback_data.source`
   - Get name from FSM data: `data = await state.get_data(); name = data.get("name")`
   - Clear FSM state now: `await state.clear()`
   - If name is missing (FSM state was cleared/expired), send error and return
   - Check limit again (race condition guard)
   - Create basket: `BasketRepository(session).create(user.id, name, source)`
   - Set as active: `repo.set_active(user.id, basket.id)`
   - Edit message: `get_text("basket_created", lang, name=name, source=source.capitalize())`
   - `await callback.answer()`

5. **`callback_basket_list`** -- `@router.callback_query(BasketCB.filter(F.action == "list"))`
   - Same logic as cmd_baskets but edits the callback message instead of sending new
   - `await callback.message.edit_text(text, reply_markup=keyboard)`
   - `await callback.answer()`

6. **`callback_view_basket`** -- `@router.callback_query(BasketCB.filter(F.action == "view"))`
   - Get basket_id from callback_data
   - Create `BasketRepository(session)`, get basket by id
   - If basket not found, answer with error
   - Set basket as active: `repo.set_active(user.id, basket.id)` (per BSKT-03 -- viewing = activating)
   - Edit message to show basket name + action buttons: `basket_actions_keyboard(basket.id, lang)`
   - `await callback.answer()`

7. **`callback_new_basket`** -- `@router.callback_query(BasketCB.filter(F.action == "new"))`
   - Check limit (same as cmd_new_basket)
   - If limit reached, answer with limit message
   - Otherwise set FSM state and prompt for name (same as cmd_new_basket but answer via callback.message.answer, not edit, since we need new message for text input)
   - `await callback.answer()`

8. **`callback_delete_basket`** -- `@router.callback_query(BasketActionCB.filter(F.action == "delete"))`
   - Get basket from repo by callback_data.basket_id
   - Show confirmation: edit message with `get_text("confirm_delete_basket", lang, name=basket.name)` and `confirm_delete_keyboard(basket.id, lang)`
   - `await callback.answer()`

9. **`callback_confirm_delete`** -- `@router.callback_query(BasketActionCB.filter(F.action == "confirm_delete"))`
   - Get basket from repo
   - Delete: `repo.delete(basket.id)`
   - Edit message: `get_text("basket_deleted", lang, name=basket.name)`
   - `await callback.answer()`

10. **`callback_basket_back`** -- `@router.callback_query(BasketActionCB.filter(F.action == "back"))`
    - Same as callback_basket_list -- show basket list
    - `await callback.answer()`

11. **`callback_charts_stub`** -- `@router.callback_query(BasketActionCB.filter(F.action == "charts"))`
    - Send stub message: `await callback.answer(get_text("charts_coming_soon", lang), show_alert=True)`
    - Per TXUX-02: Charts button is present but shows "Coming in Phase 4" alert.

12. **`callback_edit_stub`** -- `@router.callback_query(BasketActionCB.filter(F.action == "edit"))`
    - For Phase 2, this shows an alert with "Edit quantity" hint: `await callback.answer(get_text("edit_quantity_prompt", lang, name="..."), show_alert=True)`
    - Full edit flow is a reasonable Phase 2 feature but can be a simple alert for now if time-constrained. The button must be present per TXUX-02.
